## Temuan saat ini

Halaman Sekolah sudah menyimpan nama, kelas, dan zona waktu melalui satu `PUT /api/school`. Ketika sekolah belum ada, endpoint yang sama membuat sekolah dan kelas dalam satu transaksi. `schools.logo_path` sudah ada sejak migrasi 0001, tetapi saat ini hanya menjadi kolom lama di repository; halaman dan API belum mengelola logo. Desain UI-002 layar Sekolah 04/05 menampilkan satu `Simpan perubahan`, `Pilih logo`, pratinjau, dan `Hapus logo`. Tidak ada tombol Batal pada acuan. Yang terlihat hanya placeholder desain; saya tidak membuka `.data`, environment privat, atau database guru.

Penutupan semester mengambil snapshot nama sekolah/kelas melalui trigger dan membuat snapshot immutable; tabel snapshot belum menyimpan ID logo. `closeSemester` mengambil advisory lock sekolah nomor 1728 sebelum lock lain. Endpoint pengaturan saat ini mengambil row lock tanpa advisory lock. `api-auth` sudah memeriksa same-origin untuk request tulis dan endpoint Sekolah mewajibkan sesi guru. Migrasi 0005 membatasi akses runtime secara eksplisit dan setiap objek baru perlu kebijakan RLS/grant sendiri. Runner migrasi menghitung checksum pasangan file up/down, jadi migrasi baru harus memakai pasangan versioned dan migrasi 0001–0007 tetap utuh.

`h3@1.15.11` yang terpasang menyediakan `readMultipartFormData`, tetapi implementasinya memanggil `readRawBody` untuk membaca seluruh request ke buffer dan tidak menerima batas ukuran. Jangan gunakan helper itu untuk menerima file sebelum ada pembatas stream yang bekerja pada byte yang benar-benar diterima.

## Kontrak yang direkomendasikan untuk dikunci PM

1. **Satu aksi Simpan, satu transaksi metadata.** Pertahankan `PUT /api/school` dan tambahkan jalur `multipart/form-data` untuk payload profil (`metadata` JSON) serta satu bagian opsional `logo`. Pertahankan jalur JSON lama untuk kompatibilitas bila tidak ada berkas. Upload, ganti, lepas logo aktif, update profil, dan pembuatan sekolah/kelas awal harus melewati satu transaksi yang sama; jangan membuat request upload terpisah yang dapat menyimpan sebagian perubahan. Klien tidak mengirim `teacherId`, `schoolId`, path penyimpanan, atau nama file sebagai identitas aset.

2. **Draft dan pemulihan UI.** Memilih berkas hanya membuat draft/pratinjau lokal; belum mengunggah atau mengubah data tersimpan. `Hapus logo` menandai penghapusan pointer logo aktif dalam draft. Perubahan baru berlaku setelah `Simpan perubahan`; bila disertakan, Hapus hanya melepas pointer aktif dan tidak menghapus file atau pointer arsip. Jika validasi, storage, atau transaksi gagal, pertahankan isian profil dan draft berkas, tampilkan error pada halaman yang sama, dan jangan tampilkan sukses. Pembuatan sekolah awal yang gagal tidak boleh meninggalkan sekolah atau kelas parsial. Desain tidak memiliki tombol Batal; rekomendasi saya tidak menambah kontrol/modal baru. Sebelum Simpan, draft dapat dibuang dengan meninggalkan/muat ulang halaman; server tetap memegang nilai lama. Bila PM menghendaki tombol Batal eksplisit, itu perlu dikunci sebagai perubahan UI terhadap acuan.

3. **API gambar privat.** `GET /api/school` dapat menambah `logoAssetId` nullable; byte gambar disajikan hanya lewat route same-origin yang memerlukan sesi dan mengecek hubungan aset dengan sekolah/arsip milik guru. Route menurunkan MIME dari metadata hasil decoder, memberi `Cache-Control: no-store` dan `X-Content-Type-Options: nosniff`, serta tidak membocorkan path penyimpanan. Jangan membuat URL publik atau endpoint pembacaan path arbitrer.

4. **Validasi dan batas multipart.** Batasi ukuran file pada `2 * 1024 * 1024` byte dan seluruh request pada `2 MiB + 64 KiB` untuk field/boundary/header. Periksa `Content-Length` untuk penolakan awal saja; hitung dan hentikan stream jika melewati batas meskipun header hilang/tidak benar. Untuk format `metadata` dan `logo`, kandidat limit parser: satu file, satu field, paling banyak dua part, field metadata 2 KiB, nama field pendek/allowlist, dan jumlah header multipart kecil. Tolak part/field tambahan dan tandai file yang mencapai batas parser sebagai gagal; jangan menerima file terpotong.

   Periksa signature PNG/JPEG sebelum decoder, lalu pastikan format decoder cocok dengan signature, dimensi bukan nol dan masing-masing maksimal 4096, jumlah piksel maksimal 16.777.216, serta berkas benar-benar berhasil didecode. Gunakan hasil decode, bukan ekstensi atau MIME yang dikirim browser, untuk memutuskan tipe. Tolak SVG, format lain, gambar rusak/truncated, ukuran di atas batas, dan dimensi di atas batas.

5. **Penyimpanan lokal dan production guard.** Gunakan antarmuka storage kecil dengan key acak server-side (UUID) dan adapter lokal ke `.data/uploads/school-logos/`; direktori bukan static/public. Simpan bytes dengan nama turunan dari ID, bukan nama dari browser. Pastikan root berada di dalam direktori private yang diizinkan, tolak komponen symlink/escape, dan buat file eksklusif agar operasi tidak menimpa aset lain. Tulis file baru yang sudah divalidasi sebelum transaksi metadata; jika transaksi gagal, bersihkan hanya file baru milik operasi itu. File lama yang pernah dirujuk snapshot tidak dihapus. Adapter lokal hanya untuk development/fixture. Pada Vercel production, jika provider tahan lama belum disediakan, fail closed untuk upload dan read; jangan jatuh kembali ke `.data` atau `/tmp`. Pilihan object storage tetap keputusan dan pekerjaan terpisah.

## Dependency dan runtime

Kandidat multipart adalah `busboy@1.6.0`. Pemeriksaan read-only dengan Node `v24.19.0` dan npm CLI `10.9.3` menunjukkan versi itu masih latest registry pada tanggal pemeriksaan, `engines.node >=10.16.0`, dan dependency `streamsearch@^1.1.0`. Dokumentasi upstream mendukung limit `fileSize`, `files`, `fields`, `parts`, `fieldSize`, dan `headerPairs`; ia tidak memberi batas total body request, jadi penghitung byte stream terpisah tetap wajib. Node 24 berada di atas engines yang dinyatakan, tetapi integrasi Busboy dengan request stream H3/Nitro dan hasil Vercel bundle belum diuji.

Kandidat decode adalah `sharp@0.35.5`, versi registry terkini yang diperiksa; metadata menyatakan Node `>=20.9.0` dan mencantumkan binary opsional Linux x64 serta Windows x64. Dokumentasi Sharp menyarankan `failOn: 'warning'` untuk input tak tepercaya dan menyediakan `limitInputPixels`; `metadata()` saja membaca metadata, bukan membuktikan seluruh pixel berhasil didecode. Versi Node aplikasi disyaratkan `>=24.15.0 <25`, Nuxt `4.6.1`, dan Nitro Vercel disetel `nodejs24.x` di region `sin1`. Dokumentasi Vercel mencantumkan runtime Node 24.x. Keselarasan versi memenuhi preflight awal, tetapi belum membuktikan bundel Vercel memuat native Sharp yang benar atau decode berhasil pada Linux Vercel. Jangan menganggap smoke lokal Windows sebagai bukti Linux.

Metadata package dicek tanpa mengubah `package.json`/lock dan tidak ada dependency yang dipasang. Tautan acuan: [Busboy README](https://github.com/mscdex/busboy#api), [Busboy package metadata](https://github.com/mscdex/busboy/blob/master/package.json), [Sharp constructor](https://sharp.pixelplumbing.com/api-constructor/), [Sharp installation](https://sharp.pixelplumbing.com/install/), dan [versi Node.js Vercel](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions).

## Skema, arsip, audit, dan lock

Saya merekomendasikan migrasi baru berpasangan setelah 0007, misalnya `0008_school_logo_assets.up.sql` dan `.down.sql`: tabel metadata aset immutable berisi ID, pemilik sekolah, MIME terverifikasi, ukuran, dimensi, hash, waktu/pengunggah; pointer aktif nullable pada `schools`; pointer `logo_asset_id` nullable pada `semester_archive_snapshots`. Key file dihitung dari ID dan tidak menyimpan path atau nama asli. Pastikan relasi pointer hanya boleh menunjuk aset sekolah yang sama. Tambahkan trigger audit untuk metadata aset; perubahan pointer sekolah tercatat bersama actor melalui `withAuditActor`/audit row trigger yang sudah digunakan. Aktifkan RLS serta grant minimum eksplisit untuk `lab002_app`; jangan memberi update/delete aset atau grant luas. Bentuk constraint dan grant final menunggu review PM.

Trigger penutupan yang sudah memvalidasi snapshot perlu menangkap ID logo aktif pada saat closure yang dikonfirmasi. Snapshot yang sudah ada dibiarkan `logo_asset_id = NULL`; tidak ada backfill dari logo sekolah sekarang karena itu tidak membuktikan logo historis. Snapshot tetap immutable. Save yang mengubah pointer logo harus mengambil advisory lock 1728 sebelum lock row sekolah/kelas; source saat ini mengunci row sekolah lebih dulu, sedangkan closure mengambil 1728 lebih dulu, sehingga urutan save perlu dibetulkan untuk menghindari deadlock. Penutupan dan penyimpanan kemudian serial dan snapshot memuat versi sebelum atau sesudah penggantian, sesuai transaksi yang menang lebih dulu. Pada sekolah baru belum ada `school_id` untuk lock 1728: serialisasikan create per guru sebelum lookup/create, karena `FOR UPDATE` tidak mengunci row yang belum ada. Kunci/namespacenya menunggu PM; pertahankan constraint serta trigger immutable yang ada. Data sekolah, kelas, metadata file, dan pointer logo dimasukkan dalam transaksi create yang sama.
