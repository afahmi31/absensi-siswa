## Perubahan dan kontrak A–D

**A — target tetap dan input tepercaya.** Managed tetap root `.data/postgres`, loopback127.0.0.1:55432, database lab002_local/migrator, major16. Tidak ada flag URL/path/role/port baru. Helper `local-backup-managed-identity.mjs` membaca root canonical, PG_VERSION dan PID melalui guard regular/no-follow existing. Binary PG16 dan PowerShell memakai literal absolute path, canonical ancestor, handle yang sama, dev/ino/nlink/size/SHA-256 dipin. PG binaries tetap nlink1. Hanya fixed System32 powershell.exe menerima nlink1/2 karena hardlink servicing Windows yang benar-benar teramati; paket/PID/readPrivate tidak dilonggarkan. Environment child disanitasi case-insensitive, termasuk variasi lowercase PGOPTIONS; PSModulePath dihapus hanya untuk child OS query. Tidak memakai shell/PATH/profile/script eksternal.

**B — bukti proses dan endpoint.** PID file harus8baris valid dengan root/port/listen/status tepat. pg_ctl status wajib sukses dan PID tepat. CIM harus menyediakan executable/argv/creation time untuk postmaster dan backend; argv Windows diurai strict, bukan substring -D. Managed hanya menerima executable -D root; override config_file hanya untuk capability fixture internal. Tepat satu listener loopback dan established tuple sesi SQL harus dimiliki postmaster. Missing/null/denied/ambigu/timeout atau pergantian bukti menolak tanpa fallback, privilege tambahan atau menghentikan process asing.

**C — satu sesi SQL hidup.** Query identitas tidak memakai data_directory/read_all_settings. Reserved backend max1 READ ONLY memeriksa database/current_user/session_user/owner/major/server+client endpoint/backendPID/server-start. Backend OS wajib anak langsung postmaster, executable PG16 dan startup argv --forkbackend. Receipt WeakMap hanya sah untuk object sesi yang sama. SQL dan filesystem diambil ulang mengelilingi OS query; seluruh field instance harus sama. BackendPID berbeda dari listenerPID adalah baseline Windows yang benar-benar dibuktikan pada cluster sintetis, bukan asumsi bahwa backend memegang listener. Session loss tidak mengadopsi backend/receipt baru.

Koreksi **C9**: preflight awal menuntut floor(SQLstart)==PIDepoch; source PG16 menunjukkan aturan itu salah. `miscinit.c` menulis MyStartTime pada PID file, sedangkan `postmaster.c` menetapkan PgStartTime lebih kemudian. Untuk PID detik p, require processCreation < p+1detik, p <= SQLstart, processCreation <= SQLstart <= backendCreation. Tidak require p+1 <= SQLstart; startup di detik sama sah. CIM dihitung BigInt100ns dari7digit pecahan, SQL microsecond dari6digit, PID detik hanya mempunyai interval ketidakpastian1detik. Setiap nilai mentah dipin exact sepanjang operasi, tanpa delta maksimum/minimum tambahan.

Sumber primer: [PG16 miscinit.c](https://raw.githubusercontent.com/postgres/postgres/REL_16_STABLE/src/backend/utils/init/miscinit.c) sekitar1350–1355 dan [PG16 postmaster.c](https://raw.githubusercontent.com/postgres/postgres/REL_16_STABLE/src/backend/postmaster/postmaster.c) sekitar1351–1354/2499–2502. Tiga probe sintetis nonprivileged mencatat PIDepoch/SQLstart `1792617338/1792617338.293640`, `1792617358/1792617358.924948`, `1792617374/1792617374.225220`. Ketiganya same-second; nilai timestamp run gagal awal tidak tersimpan. Crossing-second valid dibuktikan fixture deterministik dan source, bukan diklaim sebagai observasi run gagal.

**D — snapshot sampai publikasi.** Exporter tetap hidup saat exported snapshot, pg_dump dan pembacaan logo. Guard diulang sebelum dump, sesudah dump dan sebelum publish. Setelah COMMIT snapshot, transaksi READ ONLY baru pada reserved backend yang sama memeriksa ledger/schema dengan catalog snapshot segar. Manifest/hash/aset/privacy/atomic checks existing tetap berlaku. Gagal membuang staging hanya melalui receipt miliknya dan mempertahankan paket final terdahulu.

Lifecycle error memakai callback onclose khusus pool create; wrapper hanya API tag/unsafe/array yang diperlukan dan menolak query baru setelah close. Gagal menutup pool operasi secara langsung (`end timeout0`), tanpa ROLLBACK/release pada reservation mati. Transaksi seluruhnya read-only. Tidak mengganti driver, reconnect/retry, global uncaughtException handler atau baseline receipt.
