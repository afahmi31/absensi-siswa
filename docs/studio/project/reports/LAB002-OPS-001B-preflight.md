## 3. Snapshot DB dan aset pada perubahan bersamaan

Usulan algoritme: buka koneksi source khusus, `BEGIN ISOLATION LEVEL REPEATABLE READ READ ONLY`; ambil `pg_export_snapshot()`. Dalam transaksi ini baca ledger/checksum/schema, tabel dan kolom yang diizinkan, row counts/digests, seluruh metadata `school_logo_assets`, union referensi `schools.active_logo_asset_id` + `semester_archive_snapshots.logo_asset_id`. Jalankan PG16 `pg_dump --format=custom --data-only --no-owner --no-acl --snapshot=<exported>` dengan daftar tabel bisnis **ditambah school_logo_assets**, snapshot exporter tetap terbuka sampai dump dan pengambilan metadata selesai. PostgreSQL mendukung sinkronisasi ini: [pg_dump16 --snapshot](https://www.postgresql.org/docs/16/app-pgdump.html), [fungsi export snapshot16](https://www.postgresql.org/docs/16/functions-admin.html#FUNCTIONS-SNAPSHOT-SYNCHRONIZATION). Tidak melakukan lock domain tambahan atau update source.

Paket membawa byte untuk **seluruh baris metadata logo dalam snapshot**, superset referensi aktif/arsip. Ini menjaga metadata orphan historis tetap lengkap tanpa membuang baris data, dan tidak menyalin file orphan dari filesystem. Metadata referensi harus resolve ke baris aset sekolah yang benar. Untuk setiap aset, adapter baca file ID+MIME yang dibangun alat sendiri, validasi regular/no-symlink/size/SHA/decode+dimensi terhadap metadata. Missing/tampered gagal seluruh paket; tidak fallback logo sekarang. UUID committed tidak ditimpa/dihapus oleh jalur source yang diamati.

Upload B atau tutup semester yang commit sesudah snapshot tidak masuk dump/daftar referensi; A pada snapshot tetap tersedia. Upload belum commit tidak terlihat dan rollback receipt-nya tidak termasuk. Perubahan yang commit sebelum snapshot seluruhnya terlihat. Copy file dilakukan di staging privat; export snapshot tetap hidup sampai selesai untuk memudahkan audit. Putus exporter/timeout adalah failure, bukan fallback snapshot baru. Perubahan migration/DDL bersamaan menyebabkan penolakan pemeriksaan schema/ledger final; tidak mencoba upgrade otomatis. Tidak menjanjikan snapshot filesystem terhadap modifikasi manual oleh pemilik OS: hash/decode harus fail jika bytes berubah.

Sequence PostgreSQL bukan baris MVCC. Jangan mengklaim last_value tepat pada snapshot saat writer bersamaan. Audit rows/IDs harus tepat; posisi sequence dump boleh lebih maju karena concurrent writer. Restore memakai nilai aman >= maksimum ID audit restored +1 dan state dump yang tervalidasi, tanpa benturan. Pada fixture idle bandingkan state sequence sesuai kontrak; pada concurrency buktikan next audit ID aman dan rows tetap snapshot lama.

## 5. Paket atomik, path, ACL dan cleanup

Direktori fixed backup diabaikan Git. Sebelum tulis, periksa setiap ancestor dengan lstat+realpath; tolak junction/symlink/UNC/reparse path yang tidak canonical. Staging private generated sibling `.pending-UUID`, mkdir exclusive + receipt identitas; ACL Windows inheritance off hanya SID owner+SYSTEM, verifikasi ACL efektif dan hentikan jika gagal. Tidak mengubah ACL `.data` atau folder guru yang lain. File wx/no-follow/0600; mode POSIX saja tidak cukup di Windows. Simpan dump/aset/manifest, fsync file, tutup handle, verifikasi seluruh hash lagi, rename staging pada volume sama ke ID final setelah pastikan tidak existing. Gunakan ID acak + lock namespace tool agar publikasi tidak menimpa final existing pada Windows; collision/unknown root ownership gagal. Tidak menyebut tahan power-loss mutlak tanpa pengujian durability filesystem.

Hanya final package lengkap yang dapat dipilih restore; pending/crash tidak dianggap sukses. Sebelum init target: batas manifest1MiB, dump256MiB, extracted SQL256MiB, perlogo2MiB, total aset256MiB/max10000 aset, duplikat JSON key/ID/path ditolak. Ini batas tool v1 yang diusulkan, bukan batas kapasitas sekolah; limit terlampaui gagal jelas tanpa partial success. Parser JSON harus mendeteksi duplicate keys, bukan JSON.parse diam-diam memilih terakhir. Path grammar hanya database.dump dan assets/UUID.ext sesuai MIME; tolak absolute/drive/UNC, dot segments, backslash, ADS/colon, case alias, reserved names, extra files, hardlink nlink>1 dan symlink di file/ancestor. Pastikan file yang dihash adalah handle bytes yang dipakai, lalu copy ke staging milik restore dan reverify agar perubahan input sesudah pemeriksaan tidak lolos.

Cleanup hanya root generated dengan canonical parent fixed, nama UUID, nonce/receipt dan identitas direktori cocok; cek setiap ancestor dan child tanpa mengikuti symlink sebelum recursive remove. Jika ownership berubah/ada junction baru, hentikan cleanup dan laporkan artefak privat tertinggal, jangan memperluas penghapusan. Stop hanya handle cluster/proses yang cocok capability; timeout/escalation signal hanya PID milik run yang diverifikasi. Tidak membunuh service/process lain atau membersihkan folder historis. Gagal stop berarti jangan recursive-delete cluster yang mungkin aktif. Error/log hanya fase, error code aman, aggregate counts/size, durasi, operation ID dan cleanup outcome; raw PostgreSQL stderr tidak dipublikasikan. SQL/temp/dump mengandung data privat; hasil uji yang dibawa ke Git hanya ringkasan sintetis.
