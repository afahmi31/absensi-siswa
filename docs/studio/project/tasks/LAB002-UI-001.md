## Scope

- Satu arah desain login email/password, tanpa pendaftaran umum atau reset password yang belum dipilih.
- Absensi satu kelas untuk satu tanggal, daftar siswa, H/S/I/A, “Tandai semua hadir”, ubah pengecualian, “Simpan”, serta jumlah siswa belum diisi.
- Rancangan layar pada HP dan laptop dengan data fiktif; pemilihan tanggal sederhana untuk membuka hari sekolah yang valid, tanpa mendesain pengaturan kalender.
- Variasi keadaan belum diisi, perubahan yang belum disimpan, menyimpan, tersimpan, simpan sebagian dan gagal menyimpan. Status visual tidak mengarang persistence/autosave atau algoritme konflik.
- Catatan interaksi dan copy ringkas; peta keputusan visual yang diajukan kepada Ardy.

## Out of scope dan larangan

Tidak coding aplikasi, scaffold/install dependency, UI prototype yang menjalankan backend, API/database/auth nyata, pemulihan akun, laporan/PDF, impor, kalender management, tutup semester, konflik dua perangkat, keputusan stack, layanan berbayar, upload/publikasi desain eksternal, Git init/commit/push atau deployment. Tidak memakai identitas siswa asli dari PDF.

## Acceptance Criteria

- AC-01: artefak visual login dan absensi tersedia untuk HP dan laptop, cukup terbaca untuk review; ukuran kanvas dicatat dan tata letak tidak saling bertumpuk.
- AC-02: login hanya email/password/Masuk; tidak ada register/reset flow yang belum disetujui.
- AC-03: default absensi belum diisi; aksi tandai hadir, ubah H/S/I/A, Simpan, dan count belum diisi terlihat. Simpan sebagian digambarkan tanpa mengubah kosong menjadi Alpa.
- AC-04: state menyimpan/berhasil/gagal dibedakan; tidak ada janji autosave, retry otomatis atau tersimpan sebelum konfirmasi sukses. Copy ditujukan kepada guru.
- AC-05: data fiktif, interaksi, perubahan visual dan batas desain tercatat; artefak tidak dipresentasikan sebagai bukti runtime atau approval desain.
- AC-06: hanya folder output yang diizinkan diubah; laporan mencantumkan self-check AC, verification aktual, risiko/unknowns dan next owner PM. Tidak ada tindakan production.
