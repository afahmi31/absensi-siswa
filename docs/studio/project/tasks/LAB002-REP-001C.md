## Tujuan dan acuan

Guru dapat mengunduh berkas PDF nyata dari laporan bulanan atau semester, terpisah dari dialog cetak browser. Gunakan model rekap REP-001A dan halaman REP-001B yang sudah diterima (baseline develop0393710). Root kode app, dokumentasi registry LAB-002. Baca PRD R11–R14, kontrak lokal C05, task induk REP-001, UI-002 layar15–19 dan review B. PM memakai skill studio-task-brief/development-plan untuk pembagian tahap, tidak coding aplikasi.

Task induk mengharuskan browser dan PDF memakai baris/header/pemisah halaman yang sama. Ini tidak boleh diam-diam diganti menjadi dua tabel yang berbeda perhitungannya atau mengurangi AC. Preflight harus mengusulkan cara menjaga kesamaan tersebut, termasuk nama panjang dan tiga ukuran kertas. Jika memerlukan kontrak endpoint/layout tambahan atau perubahan preview, PM meninjaunya dahulu. Jangan mengubah API/flow atau memasang paket sebelum review preflight.

## Scope implementasi setelah PM review

- PDFKit server-side, versi tepat dipin setelah kompatibilitas diperiksa; Node24/npm10.9.3/lockfile. Dependency ini sudah dipilih kontrak lokal. Tidak Chromium server, layanan render eksternal atau font jarak jauh. Type package lokal hanya bila diperlukan; laporkan versi.
- Endpoint PDF GET terlindungi, validasi semester/mode/bulan/paper, ownership sama seperti model existing, no-store/nosniff, MIME application/pdf dan Content-Disposition attachment dengan nama aman. PDF valid %PDF, jangan mengirim sukses untuk error/berkas kosong.
- Ukuran tepat A4 297×210mm, F4 330×216mm, Letter279,4×215,9mm. Laporan semester kumpulan bulan kronologis, bulan baru pada halaman baru, header berulang, baris utuh, semua31kolom dan S/I/A, nama panjang membungkus, NIPD/JK optional kosong, tanpa tanda tangan/penanda kosong tambahan.
- Model, status efektif, metadata arsip, jumlah dan urutan sama dengan laporan existing. Tidak mengubah absensi, kalender, arsip, akun, schema/grant/pool/driver. Logo belum tersedia dan tidak dipalsukan; dependency logo privat/arsip tetap pada OPS terpisah sebelum task induk lengkap.
- Tombol Unduh PDF di halaman laporan mengikuti pemilihan yang valid dan sudah ditampilkan. Sebelum client siap, saat loading, hasil kosong atau filter stale: nonaktif seperti Cetak. Saat unduh, feedback jelas, cegah klik ganda, pilihan bertahan jika gagal dan bisa dicoba lagi. Tidak mengklaim file tersimpan ke disk sebelum browser menerima berkas. Tidak menambah modal atau flow akun.
- Jangan mengirim HTML/login/error JSON sebagai unduhan PDF. Kegagalan/sesi berakhir menggunakan pola pesan aman existing. Nama berkas tidak mengambil raw input/nama sekolah arbitrer ke header. Data pengguna tidak disisipkan sebagai markup/script. Jangan mencatat isi laporan/data siswa pada log.
